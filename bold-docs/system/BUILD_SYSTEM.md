# Build System Specification

## Purpose

This document defines how BootstrapSpark is installed, developed, validated, built, analyzed, and prepared for deployment. BootstrapSpark and TailwindSpark are companion demonstration sites, so their build contracts should stay aligned where the styling framework does not require a difference.

## Runtime Contract

| Requirement         | Value                 |
| ------------------- | --------------------- |
| Package manager     | npm `12.2.0`          |
| Node.js             | `>=26.0.0`            |
| Application bundler | Vite 8 (Rolldown)     |
| Language compiler   | TypeScript            |
| Linter              | ESLint                |
| Test runner         | Vitest                |
| Formatter           | Prettier              |
| Styling             | Bootstrap 5 plus SCSS |

Install dependencies from the repository root with `npm ci`.

The repository includes `.nvmrc`, `.node-version`, and `.npmrc`. Version managers should select Node.js `26.0.0`, and npm enforces the declared engine contract during install.

## Required Root Commands

| Command                 | Purpose                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------- |
| `npm run build`         | Creates the deterministic production `docs/` artifact from local or committed source. |
| `npm run build:deploy`  | Produces the deployable static site artifact for Azure Static Web Apps.               |
| `npm run build:ci`      | Runs the expected CI sequence: lint, type-check, coverage, and deploy build.          |
| `npm run dev`           | Starts local Vite and Sass watch tasks.                                               |
| `npm run preview`       | Serves the built `docs/` artifact locally through Vite preview.                       |
| `npm run sync:data`     | Explicitly refreshes remote-backed repository data into `.build/`.                    |
| `npm run lint`          | Runs ESLint.                                                                          |
| `npm run type-check`    | Runs TypeScript validation without emit.                                              |
| `npm run test`          | Runs Vitest.                                                                          |
| `npm run test:coverage` | Runs Vitest with coverage.                                                            |
| `npm run format`        | Applies Prettier formatting.                                                          |
| `npm run format:check`  | Checks Prettier formatting.                                                           |
| `npm run build:analyze` | Builds and writes `reports/bundle-analysis.html`.                                     |
| `npm run clean`         | Removes generated build output and Vite cache.                                        |

## Deterministic Builds

Normal production, CI, deploy, and preview commands must not refresh remote data. `npm run build` prepares `.build/data/repositories.json` from the committed fallback snapshot before Vite copies it into `docs/data/`.

Use `npm run sync:data` only when the remote repository feed should be refreshed. Review any generated data changes before committing source snapshots.

## Deployment Artifact

The deployable site is the repository-root `docs/` directory generated by Vite. A valid artifact includes HTML, hashed JavaScript and CSS, copied static assets, generated sitemap and robots files, `.nojekyll`, and build-consumable static data.

Azure Static Web Apps is the primary deployment target. CI prebuilds `docs/` with Node.js `>=26.0.0` and npm `12.2.0`; the Azure deploy action uploads that prebuilt artifact rather than rebuilding the app.

## Bundle Analysis

Bundle analysis is opt-in. It does not run during normal build, CI, or deploy commands. Run:

```powershell
npm run build:analyze
```

The report is written to:

```text
reports/bundle-analysis.html
```

## Dependency Maintenance

Use `npm audit`, `npm outdated`, and `npm run update:check` (ncu). The [dependency usage inventory](NPM_DEPENDENCIES.md) documents every retained direct package, removals, and the TypeScript 6 compatibility constraint. npm engines, packageManager, CI and contributor docs use 12.2.0.

## Build Warning Policy

The shared React, React DOM, and scheduler runtime is emitted as `react-vendor` by `scripts/build-policy.ts`; other modules retain Vite's automatic route splitting. The default 500 kB minified JavaScript warning threshold remains enabled.

Only `INVALID_ANNOTATION` warnings from `node_modules/@microsoft/signalr/dist/esm/Utils.js` and `node_modules/zod/v4/core/regexes.js` and `node_modules/zod/v4/core/util.js` are ignored. These dependency comments contain misplaced pure annotations that the bundler removes. All other warning codes and files are forwarded. Regression tests cover Windows and POSIX paths and warning forwarding.

## Intentional Divergences From TailwindSpark

| Area              | BootstrapSpark                                                            |
| ----------------- | ------------------------------------------------------------------------- |
| Styling           | Bootstrap 5 plus SCSS instead of Tailwind CSS.                            |
| Repository layout | Single Vite application unless a monorepo is intentionally adopted later. |
| Linting           | ESLint remains required by the BootstrapSpark backbone.                   |
| Deployment output | `docs/` remains the static artifact for Azure Static Web Apps.            |

## Validation

Build-system changes are complete only after running under Node.js `>=26.0.0` and npm `12.2.0`, or recording why the local runtime prevents running:

```powershell
npm ci
npm run lint
npm run type-check
npm run test:coverage
npm run build
npm run build:deploy
npm run build:ci
npm run build:analyze
git diff --check
```
